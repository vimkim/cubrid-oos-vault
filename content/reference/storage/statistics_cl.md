### Role in the System

`statistics_cl.c` is one side of the client-server statistics split. The query optimizer (running on the client) needs cardinality and selectivity information to produce good query plans. This file is responsible for:

1. Requesting a serialized statistics blob from the server via the network layer.
2. Deserializing that blob into heap-allocated `CLASS_STATS` / `ATTR_STATS` / `BTREE_STATS` structures living in the **workspace** (`db_ws_alloc`).
3. Providing utility functions to dump statistics to a `FILE*` stream for debugging.
4. Providing an alternative NDV collection path that bypasses the server-maintained catalog and instead executes a live SQL query (`COUNT(DISTINCT col)`) directly against the table — useful for fresh or sampling-based NDV computation.

### `BTREE_STATS` (struct btree_stats)

Represents statistical information about one B+tree index.

| Field | Type | Description |
|---|---|---|
| `btid` | `BTID` | B-tree identifier: `{vfid.volid, vfid.fileid, root_pageid}`. Used as a primary key to match index to table attribute |
| `leafs` | `int` | Number of leaf pages **including** overflow pages. Used by the optimizer to estimate I/O cost |
| `pages` | `int` | Total pages in the B+tree (internal + leaf + overflow). Used to compute index height and I/O estimates |
| `height` | `int` | Height of the B+tree. A height-1 tree is a single leaf page (all data fits in root). Used for seek-cost estimation |
| `keys` | `int` | Total number of key entries (not distinct — a multi-value index can have more keys than rows). Capped during deserialization to `heap_num_objects` |
| `has_function` | `int` | Boolean: 1 if this is a function-based index, 0 otherwise. Used by optimizer to detect functional indexes |
| `key_type` | `TP_DOMAIN *` | Pointer to the domain (type) of the index key. Deserialized via `or_unpack_domain()`. For composite indexes this is `DB_TYPE_MIDXKEY` |
| `pkeys_size` | `int` | Number of valid entries in `pkeys[]`. For a simple (single-column) index this is 1. For a composite (MIDXKEY) index, equals `tp_domain_size(key_type->setdomain)`, capped at `BTREE_STATS_PKEYS_NUM` (8) |
| `pkeys` | `int *` | Heap-allocated array of partial-key cardinalities. `pkeys[0]` = number of distinct values for the first key column alone, `pkeys[1]` = distinct values for columns 1+2, ..., `pkeys[pkeys_size-1]` = distinct values for all columns. Used by the optimizer for composite index selectivity |
| `dedup_idx` | `int` | Index into `pkeys[]` for deduplication support (`SUPPORT_DEDUPLICATE_KEY_MODE`). A value of `>= 0` means the index has a dedup suffix; the effective cardinality is up to `pkeys[dedup_idx]`. A negative value means no deduplication. Used by `stats_dump()` to limit displayed cardinality |

**Memory**: `pkeys` is individually heap-allocated via `db_ws_alloc`. It must be freed via `db_ws_free` before freeing the `BTREE_STATS` array.

### 6.2 `stats_client_unpack_statistics` — Core deserialization (static)

```c
static CLASS_STATS *stats_client_unpack_statistics (char *buf_p);
```

**Linkage**: Static (internal to translation unit)

**Parameters**:
- `buf_p` — Pointer to a network buffer containing the serialized statistics blob packed by `xstats_get_statistics_from_server()` on the server side

**Return value**: Pointer to a newly allocated `CLASS_STATS` in workspace memory, or NULL on error.

**Algorithm**:

*Phase 1 — CLASS_STATS header:*
1. Guard: return NULL if `buf_p == NULL`.
2. Allocate `CLASS_STATS` via `db_ws_alloc`.
3. Read `time_stamp` as `OR_GET_INT`, advance 4 bytes.
4. Read `heap_num_objects` as `OR_GET_INT`, advance 4 bytes. Clamp to 0 if negative (with `assert(false)`).
5. Read `heap_num_pages` as `OR_GET_INT`, advance 4 bytes. Clamp to 0 if negative.
6. If either `heap_num_objects == 0` or `heap_num_pages == 0`, force `time_stamp = 0` so the caller knows to re-fetch statistics.
7. Read `n_attrs` as `OR_GET_INT`. If 0, free and return NULL.
8. Allocate `attr_stats` array of `n_attrs * sizeof(ATTR_STATS)`.

*Phase 2 — Per-attribute loop (i = 0..n_attrs-1):*
9. For each `ATTR_STATS`:
   - Read `id` (4 bytes), `type` (4 bytes), `n_btstats` (4 bytes), `ndv` (8 bytes via `OR_GET_INT64`).
   - If `n_btstats <= 0`: set `bt_stats = NULL`, continue to next attribute.
   - Allocate `bt_stats` array of `n_btstats * sizeof(BTREE_STATS)`, zeroed with `memset`.

*Phase 3 — Per-BTREE_STATS loop (j = 0..n_btstats-1):*
10. For each `BTREE_STATS`:
    - Read `btid` via `OR_GET_BTID`, advance `OR_BTID_ALIGNED_SIZE` (12 bytes).
    - Read `leafs`, `pages`, `height`, `has_function`, `keys`, `dedup_idx` — each 4 bytes.
    - Call `or_unpack_domain(buf_p, &btree_stats_p->key_type, 0)` — this deserializes the `TP_DOMAIN` and advances the pointer; the domain is registered in the domain cache (not workspace-allocated separately).
    - Determine `pkeys_size`: if key type is `DB_TYPE_MIDXKEY`, `pkeys_size = tp_domain_size(key_type->setdomain)`; otherwise 1.
    - Cap `pkeys_size` at `BTREE_STATS_PKEYS_NUM` (8).
    - Allocate `pkeys` array of `pkeys_size * sizeof(int)`.
    - Read `pkeys[k]` for k = 0..pkeys_size-1, each 4 bytes.

*Phase 4 — Validation:*
11. Assert `heap_num_objects >= 0`.
12. For every `BTREE_STATS`, cap `keys = MIN(keys, heap_num_objects)` — an index cannot have more keys than rows.
13. For every `pkeys[k]`, cap `pkeys[k] = MIN(pkeys[k], keys)` — partial key count cannot exceed total key count.

**Error handling**:
- On any `db_ws_alloc` failure: call `stats_free_statistics(class_stats_p)` to release all already-allocated memory, then return NULL.
- The `or_unpack_domain` call does not return an error code — it returns the advanced buffer pointer. Domain allocation failure is silent at this level.

**Callers**: Only `stats_get_statistics()` (same file).

**Callees**: `db_ws_alloc`, `OR_GET_INT`, `OR_GET_INT64`, `OR_GET_BTID`, `or_unpack_domain`, `tp_domain_size`, `TP_DOMAIN_TYPE`, `db_ws_alloc` (for `pkeys`), `stats_free_statistics`, `memset`, `MIN`.

### 6.6 `stats_get_ndv_by_query` — Live NDV via SQL execution

```c
int stats_get_ndv_by_query (const MOP class_mop, CLASS_ATTR_NDV *class_attr_ndv,
                             FILE *file_p, int with_fullscan);
```

**Linkage**: External

**Parameters**:
- `class_mop` — MOP of the class to analyze
- `class_attr_ndv` — Output structure; caller must pass a zeroed `CLASS_ATTR_NDV`
- `file_p` — Optional diagnostic output stream (may be NULL; if not NULL, the generated SQL is printed before execution)
- `with_fullscan` — `STATS_WITH_FULLSCAN` (true) for a complete scan; `STATS_WITH_SAMPLING` (false) for a sampling scan using the `/*+ SAMPLING_SCAN */` hint

**Return value**: `NO_ERROR` on success; `ER_FAILED` or query error code on failure.

**Algorithm**:

*Phase 1 — Non-class guard:*
1. If `!db_is_class(class_mop)`: this is a virtual class or non-heap entity. Set `attr_cnt = 0`, allocate a single `ATTR_NDV`, set `ndv = 0`, `id = 0`, jump to `end`.

*Phase 2 — Count attributes:*
2. Get class name via `db_get_class_name()`.
3. Iterate over `db_get_attributes_force()` to count `attr_cnt`.
4. Allocate `attr_ndv` array of `attr_cnt + 1` entries (the +1 is for the trailing `count(*)` total).

*Phase 3 — Build SELECT list:*
5. Call `stats_make_select_list_for_ndv(class_mop, &class_attr_ndv->attr_ndv)` to build a comma-separated `count(distinct [col])` list. On failure, return `ER_FAILED`.

*Phase 4 — Assemble SQL:*
6. Choose query template based on `with_fullscan`:
   - Full scan: `"SELECT %s FROM [%s]"`
   - Sampling: `"SELECT /*+ SAMPLING_SCAN */ %s FROM [%s]"`
7. Allocate `query_buf` of size `strlen(select_list) + strlen(class_name) + 40`.
8. `snprintf(query_buf, ...)` to produce the final SQL string.
9. Optionally print the SQL to `file_p`.

*Phase 5 — Execute and collect results:*
10. `db_compile_and_execute_local(query_buf, &query_result, &query_error)` — executes the SQL in the current session context.
11. `db_query_first_tuple(query_result)` — position cursor on the first (and only) row.
12. For each attribute `i`: `db_query_get_tuple_value(query_result, i, &value)`. Extract `DB_GET_BIGINT(&value)`. If the result is 0 (all NULLs in the column), set NDV to 1 — this avoids a selectivity of 0 in the optimizer.
13. Read the final `count(*)` column at position `i` (after the loop).

*Label `end` cleanup:*
14. `free_and_init(select_list)` if allocated.
15. `free_and_init(query_buf)` if allocated.
16. `db_query_end(query_result)` if not NULL; set to NULL.

**Error handling**: Uses `goto end` for cleanup on every error path. Returns `ER_FAILED` on `malloc` failure. Propagates `db_compile_and_execute_local` and `db_query_get_tuple_value` errors.

**Known quirk**: The NDV minimum clamping (`ndv = 0 ? 1 : ndv`) means even columns with all-NULL values are reported as having 1 distinct value. This prevents division-by-zero in the optimizer's selectivity calculations.

**Callers**: `stats_ndv_dump()` (same file), and presumably `sm_update_statistics()` in `schema_manager.c` (the stats update pipeline).

**Callees**: `db_is_class`, `db_get_class_name`, `db_get_attributes_force`, `db_attribute_next`, `malloc`, `stats_make_select_list_for_ndv`, `db_compile_and_execute_local`, `db_query_first_tuple`, `db_query_get_tuple_value`, `DB_GET_BIGINT`, `db_query_end`, `free_and_init`, `fprintf`, `snprintf`.

### 6.7 `stats_make_select_list_for_ndv` — SQL SELECT list builder

```c
char *stats_make_select_list_for_ndv (const MOP class_mop, ATTR_NDV **attr_ndv);
```

**Linkage**: External

**Parameters**:
- `class_mop` — MOP for the class; used to iterate attributes
- `attr_ndv` — Double pointer to the `ATTR_NDV` array; the function fills in `attr_ndv[i].id` for each attribute column, and `attr_ndv[attr_cnt].id = -1` for the count(*) entry. The array must already be allocated by the caller.

**Return value**: A `malloc`-allocated C string containing the SQL select-list, or NULL on allocation failure. The caller is responsible for freeing with `free_and_init`.

**Algorithm**:
1. Allocate initial `select_list` buffer of 1024 bytes.
2. Iterate `db_get_attributes_force()` over all attributes:
   a. Check the attribute's domain type:
      - If LOB type (`TP_IS_LOB_TYPE`), JSON (`DB_TYPE_JSON`), or `VARCHAR` with precision > `STATS_MAX_PRECISION` (4000): substitute `"cast (-1 as BIGINT), "` — these types are skipped for NDV computation. The -1 sentinel value signals the optimizer to ignore NDV for this column.
      - Otherwise: emit `"count(distinct [colname]), "`.
   b. If the running `select_list` would overflow the buffer, `realloc` in 1024-byte increments.
   c. `strcat` the column fragment into `select_list`.
   d. Record `attr_ndv[i].id = db_attribute_id(att)`.
   e. Advance to next attribute.
3. Append `"count(*)"` to the list (the final aggregate for total row count). Set `attr_ndv[i].id = -1` as a sentinel.
4. Return `select_list`.

**Buffer growth strategy**: The buffer starts at 1024 bytes and grows by 1024 on overflow during the column loop. For the final `count(*)` append, the buffer grows by only 10 bytes — this is precise but unusually small (safe because `strlen("count(*)")` = 8).

**Error handling**: Jumps to `end` label on `realloc` failure, frees `select_list`, returns NULL. Note a subtle bug-risk: if the final `count(*)` realloc fails, the code falls through to `end` correctly. However, there is a potential issue: if `realloc` fails inside the column loop and `select_buf == NULL`, the code sets `select_buf = NULL` and goes to `end`, but `select_list` still points to the old (now potentially invalid if `realloc` freed it) buffer. The implementation guards against this by only assigning `select_list = select_buf` after confirming `select_buf != NULL`.

**Callers**: `stats_get_ndv_by_query()` (same file).

**Callees**: `db_get_attributes_force`, `db_attribute_next`, `db_attribute_domain`, `TP_IS_LOB_TYPE`, `TP_DOMAIN_TYPE`, `DB_TYPE_JSON`, `TP_IS_CHAR_TYPE`, `db_attribute_name`, `db_attribute_id`, `malloc`, `realloc`, `strcat`, `snprintf`, `strlen`, `free_and_init`.

### 6.8 `stats_adjust_sampling_weight` — Inline helper (header-defined)

```c
STATIC_INLINE int stats_adjust_sampling_weight (INT64 sampling_ndv, int sampling_weight);
```

**Linkage**: Inline (defined in `statistics.h`, available to all build modes)

**Algorithm**:
- If `sampling_weight <= 1`: return unchanged.
- Compute `min_NDV = NUMBER_OF_SAMPLING_PAGES * EXPECTED_ROWS_PER_PAGE / 100` = `5000 * 20 / 100` = 1000.
- If `sampling_ndv < min_NDV`: return `MAX(sampling_weight * sampling_ndv / min_NDV, 1)` — apply a proportional weight reduction. This prevents over-counting NDV for columns with many duplicates in the sample.
- Otherwise: return `sampling_weight` unchanged.

**Purpose**: When sample data shows highly duplicate values (NDV < 1% of sample rows), the weight applied to extrapolate full-table NDV is reduced proportionally. This corrects for the statistical bias when the sample itself is largely uniform.

**Callers**: Used in `statistics_sr.c` (server-side statistics computation).

## 7. Key Algorithms & Logic Flows

### 7.1 Client-Side Statistics Fetch Flow

```
Optimizer requests statistics for class OID X
  |
  v
sm_get_class_with_statistics(classop)         [schema_manager.c]
  |
  +-- class->stats == NULL?
  |     YES -> flush class to server -> stats_get_statistics(oid, 0, &stats)
  |     NO  -> stats_get_statistics(oid, class->stats->time_stamp, &stats)
  |              if stats != NULL: replace cached; if NULL: use cached
  |
  v
stats_get_statistics(class_oid_p, time_stamp, stats_p)   [statistics_cl.c]
  |
  v
stats_get_statistics_from_server(oid, ts, &length, &buf)  [network_interface_cl.c]
  |
  +-- CS_MODE: net_client_request2(NET_SERVER_QST_GET_STATISTICS)
  |     -> [network] -> srvstat_get_statistics() on server
  |                  -> xstats_get_statistics_from_server()  [statistics_sr.c]
  |                  <- serialized blob (or NULL if timestamp matches)
  |
  +-- SA_MODE: enter_server() -> xstats_get_statistics_from_server() directly
  |
  v
stats_client_unpack_statistics(buf)           [statistics_cl.c]
  |
  +-- Deserialize CLASS_STATS header (time_stamp, heap_num_objects, heap_num_pages, n_attrs)
  +-- Allocate CLASS_STATS + ATTR_STATS[] in workspace (db_ws_alloc)
  +-- For each attribute: deserialize id, type, n_btstats, ndv
  +-- For each btree: deserialize btid, leafs, pages, height, has_function, keys, dedup_idx
  +-- For each btree: or_unpack_domain() for key_type
  +-- For each btree: compute pkeys_size, allocate pkeys[], deserialize pkeys[k]
  +-- Validate: cap keys and pkeys[k] against heap_num_objects
  |
  v
CLASS_STATS* returned to optimizer
```

### 7.2 Timestamp-Based Cache Invalidation

The protocol uses a simple timestamp comparison for cache coherency:

1. **First fetch** (cold cache): client sends `time_stamp = 0`. Server always returns data.
2. **Subsequent fetches** (warm cache): client sends its cached `time_stamp`. Server compares to its internal `stats_get_time_stamp()`. If equal, server returns NULL buffer (no data). If different (stats updated), server returns new serialized data.
3. **Forced refresh** (stale stats): statistics are cleared on the client side (e.g., after a schema change), and timestamp 0 is sent again.
4. **Suspicious data**: if the unpacked statistics show `heap_num_objects == 0` or `heap_num_pages == 0`, the client forces `time_stamp = 0` on the unpacked structure. This means the next call will trigger a fresh fetch even if the server's timestamp matched, because the 0 values are considered unreliable (the table may have rows that were not yet reflected in the catalog).

### 7.3 On-Wire Serialization Format

The buffer produced by `xstats_get_statistics_from_server` on the server and consumed by `stats_client_unpack_statistics` on the client follows this layout (big-endian byte order, word-aligned):

```
[CLASS_STATS header]
  4 bytes  : time_stamp (OR_INT)
  4 bytes  : heap_num_objects (OR_INT)
  4 bytes  : heap_num_pages (OR_INT)
  4 bytes  : n_attrs (OR_INT)

[For each of n_attrs attributes]
  4 bytes  : attr.id (OR_INT)
  4 bytes  : attr.type (OR_INT, DB_TYPE enum)
  4 bytes  : attr.n_btstats (OR_INT)
  8 bytes  : attr.ndv (OR_INT64)

  [For each of n_btstats btrees]
    12 bytes : btree.btid (OR_BTID_ALIGNED_SIZE)
    4 bytes  : btree.leafs (OR_INT)
    4 bytes  : btree.pages (OR_INT)
    4 bytes  : btree.height (OR_INT)
    4 bytes  : btree.has_function (OR_INT)
    4 bytes  : btree.keys (OR_INT)
    4 bytes  : btree.dedup_idx (OR_INT)
    variable : btree.key_type (or_pack_domain / or_unpack_domain)
    4 * pkeys_size bytes : btree.pkeys[] (OR_INT each)
```

The key_type domain is variable-length — its size is determined at deserialization time by `or_unpack_domain`, which advances the buffer pointer and returns the new position.

### 7.4 NDV Live Query Flow

```
stats_ndv_dump(class_name, fp)
  |
  v
stats_get_ndv_by_query(class_mop, &ndv, fp, STATS_WITH_SAMPLING)
  |
  +-- Count attributes (db_get_attributes_force / db_attribute_next)
  +-- Allocate ATTR_NDV[n+1]
  +-- stats_make_select_list_for_ndv() -> builds SQL select list:
  |     "count(distinct [col1]), count(distinct [col2]), ..., count(*)"
  |     (LOB/JSON/wide-VARCHAR columns replaced with "cast(-1 as BIGINT)")
  |
  +-- Build full SQL:
  |     SAMPLING: "SELECT /*+ SAMPLING_SCAN */ <list> FROM [classname]"
  |     FULLSCAN: "SELECT <list> FROM [classname]"
  |
  +-- db_compile_and_execute_local() -> executes SQL in current session
  +-- db_query_first_tuple() -> single-row result
  +-- db_query_get_tuple_value(i) for i=0..n-1 -> ATTR_NDV[i].ndv
  +-- db_query_get_tuple_value(n) -> total count (ATTR_NDV[n].ndv)
  |
  v
CLASS_ATTR_NDV populated; caller prints or uses for statistics update
```

## 8. Concurrency & Thread Safety

`statistics_cl.c` itself contains **no synchronization primitives** (no mutexes, spinlocks, or atomic operations). Thread safety is entirely delegated to the layers below:

1. **Workspace allocator** (`db_ws_alloc`): The workspace is a per-connection/per-session structure in the client library. In CS_MODE, each client process has its own workspace, so no inter-process locking is needed for the allocation itself. In SA_MODE, the single process handles one session at a time via `enter_server`/`exit_server`.

2. **Network layer** (`stats_get_statistics_from_server`): In CS_MODE, `net_client_request2` operates on a connection that is already serialized per client thread. The server handles concurrent requests via thread-per-connection pool and its own locking.

3. **SA_MODE server calls**: The `enter_server` / `exit_server` wrappers in `network_interface_cl.c` handle thread context switching. `xstats_get_statistics_from_server` takes a `THREAD_ENTRY*` and may acquire catalog locks internally.

4. **DB_QUERY_RESULT**: The `db_compile_and_execute_local` / `db_query_*` family operates within a single transaction context. These are not thread-safe to share, but `stats_get_ndv_by_query` allocates and frees its own `query_result` locally within the function.

5. **`CLASS_STATS` ownership**: Once returned to `schema_manager.c`, the `CLASS_STATS` structure is owned by the `SM_CLASS->stats` field. Schema manager code is responsible for protecting concurrent access to `SM_CLASS` through the workspace lock and fetch-class protocol.

**Conclusion**: `statistics_cl.c` is inherently single-threaded in its execution path; concurrency safety is provided by the surrounding infrastructure (network protocol, workspace, schema lock).

## 9. Memory Management

### Allocation strategy

All statistics objects (`CLASS_STATS`, `ATTR_STATS[]`, `BTREE_STATS[]`, `pkeys[]`) are allocated in the **workspace** using `db_ws_alloc`. The workspace is a per-session managed memory area that allows bulk deallocation at transaction boundaries. This is standard for client-side schema/catalog objects in CUBRID.

The NDV query path (`stats_get_ndv_by_query`, `stats_make_select_list_for_ndv`) uses plain `malloc` / `realloc` for intermediate buffers (`select_list`, `query_buf`, `attr_ndv`). These are explicitly freed with `free_and_init` before function return.

### Allocation tree

```
CLASS_STATS                         db_ws_alloc
  ATTR_STATS[]  (n_attrs)           db_ws_alloc
    BTREE_STATS[]  (n_btstats)      db_ws_alloc + memset zero
      pkeys[]  (pkeys_size)         db_ws_alloc
```

### Ownership model

- `CLASS_STATS*` returned by `stats_get_statistics` is owned by the caller (`SM_CLASS->stats` in `schema_manager.c`).
- The caller is responsible for calling `stats_free_statistics()` when done (typically when stats are refreshed or the class is evicted from the workspace).
- The macro `stats_free_statistics_and_init(stats)` is the preferred idiom: it frees and sets the pointer to NULL atomically in a `do { } while(0)` block.

### Deallocation

```c
stats_free_statistics(class_statsp)
  for each ATTR_STATS[i]:
    for each BTREE_STATS[j]:
      db_ws_free(pkeys[j])         // innermost: pkeys array
    db_ws_free(bt_stats[i])        // btree stats array
  db_ws_free(attr_stats)           // attribute stats array
db_ws_free(class_statsp)           // top-level struct
```

The `key_type` (`TP_DOMAIN*`) field is **NOT freed** here — domains are reference-counted and managed by the domain cache. Freeing them here would corrupt the cache.

### Memory leak guards in unpack

`stats_client_unpack_statistics` implements a defensive "unwind on error" pattern:

```c
attr_stats_p->bt_stats = db_ws_alloc(...);
if (attr_stats_p->bt_stats == NULL) {
    stats_free_statistics (class_stats_p);   // free everything allocated so far
    return NULL;
}
```

This pattern is repeated twice: once for `bt_stats` allocation and once for `pkeys` allocation. Because `stats_free_statistics` handles NULL sub-pointers gracefully, this partial-unwind is safe.

## 10. Error Handling

`statistics_cl.c` follows the CUBRID C error model: return codes checked against `NO_ERROR`, errors propagated up the call stack, and `er_set` used by lower layers to record error details.

### Error propagation table

| Function | Error sources | How handled |
|---|---|---|
| `stats_get_statistics` | `stats_get_statistics_from_server` returns non-zero | Returned directly to caller; `*stats_p` left NULL |
| `stats_get_statistics` | `stats_client_unpack_statistics` returns NULL | NOT treated as an error; function returns `NO_ERROR` with `*stats_p == NULL` |
| `stats_client_unpack_statistics` | `db_ws_alloc` returns NULL | Calls `stats_free_statistics` + returns NULL |
| `stats_free_statistics` | None | Void function; ignores all errors |
| `stats_dump` | `sm_find_class` returns NULL | Prints `er_msg()` to `file_p`; returns void |
| `stats_dump` | `sm_get_class_with_statistics` returns NULL | Returns void silently |
| `stats_ndv_dump` | `sm_find_class` returns NULL | Prints error; returns |
| `stats_ndv_dump` | `stats_get_ndv_by_query` fails | Jumps to `end`; cleanup occurs |
| `stats_get_ndv_by_query` | `malloc` fails | Returns `ER_FAILED` |
| `stats_get_ndv_by_query` | `stats_make_select_list_for_ndv` returns NULL | Returns `ER_FAILED` |
| `stats_get_ndv_by_query` | `db_compile_and_execute_local` error | Jumps to `end`; error code returned |
| `stats_get_ndv_by_query` | `db_query_get_tuple_value` error | Jumps to `end`; error code returned |
| `stats_make_select_list_for_ndv` | `malloc`/`realloc` fails | Jumps to `end`; frees buffer; returns NULL |

### Assertion usage

Several `assert(false)` calls guard data invariants:

```c
// Should never happen: wire data must be non-negative
if (class_stats_p->heap_num_objects < 0) {
    assert (false);
    class_stats_p->heap_num_objects = 0;
}
```

In debug builds, these trigger a crash to surface data corruption. In release builds, the `assert` is a no-op and the code self-corrects by clamping to 0.

```c
// Correctness invariant after computation
assert (btree_stats_p->pkeys_size <= BTREE_STATS_PKEYS_NUM);
assert (bt_stats_p->dedup_idx != 0);   // in stats_dump: 0 is invalid sentinel
```

## 11. Integration Points

### 11.1 statistics_sr.c (server side)

`statistics_cl.c` is the client counterpart of `statistics_sr.c`. The server provides:

- `xstats_get_statistics_from_server(thread_p, class_id, timestamp, &length)` — serializes `CLASS_STATS` into a wire buffer using `or_pack_*` functions, mirroring the `OR_GET_*` unpacking in `stats_client_unpack_statistics`.
- `xstats_update_statistics(thread_p, classoid, with_fullscan, class_attr_ndv)` — performs a full heap scan to recompute statistics, optionally using the `class_attr_ndv` NDV values.
- `stats_get_time_stamp()` — returns the server's current statistics timestamp.

The serialization contract between the two files is implicit — both sides must use the same field order and sizes. Any schema change to `CLASS_STATS`, `ATTR_STATS`, or `BTREE_STATS` requires coordinated changes to both pack (server) and unpack (client) routines.

### 11.2 network_interface_cl.c (client network layer)

`stats_get_statistics_from_server` in `network_interface_cl.c` is the glue layer:

**CS_MODE path**:
```c
// Packs: OID (12 bytes) + int timestamp (4 bytes) -> request buffer
ptr = or_pack_oid (request, classoid);
ptr = or_pack_int (ptr, (int) timestamp);
// Sends via NET_SERVER_QST_GET_STATISTICS opcode
net_client_request2(NET_SERVER_QST_GET_STATISTICS, ...);
// Server handler: srvstat_get_statistics() in network_interface_sr.cpp
//   -> xstats_get_statistics_from_server()
```

**SA_MODE path**:
```c
THREAD_ENTRY *thread_p = enter_server ();
*stats_buffer = xstats_get_statistics_from_server (thread_p, classoid, timestamp, length_ptr);
exit_server (*thread_p);
return NO_ERROR;
```

In SA_MODE, there is no network; `stats_get_statistics_from_server` always returns `NO_ERROR` regardless of the underlying call result (the error would only manifest as NULL `*stats_buffer`).

### 11.3 schema_manager.c (primary consumer)

The primary consumer of `statistics_cl.c` is `schema_manager.c`, specifically:

- **`sm_get_class_with_statistics(classop)`** — The main entry point for the query optimizer. Calls `stats_get_statistics` with either timestamp 0 (first time) or the cached timestamp (subsequent calls). Handles the returned stats: replaces the old `SM_CLASS->stats` if new data arrived.
- **`sm_get_statistics_force(classop)`** — Forces a fresh fetch (timestamp 0) regardless of cache state.
- **`sm_update_statistics(classop, with_fullscan)`** / **`sm_update_all_statistics`** — After calling the server to recompute statistics, calls `stats_get_statistics` with timestamp 0 to refresh the client cache.

The class `SM_CLASS->stats` field is the in-memory cache of statistics. `statistics_cl.c` allocates and populates it; `schema_manager.c` owns its lifecycle.

### 11.4 object_print.c (diagnostic consumer)

`src/object/object_print.c` calls `stats_dump()` as part of the `"showstat"` debug path in the `obj_print_help_class()` function. This is accessible from `csql` via the `\d` describe command when statistics display is requested.

### 11.5 Query optimizer (indirect consumer)

The query optimizer in `src/optimizer/` accesses `SM_CLASS->stats` (populated by `statistics_cl.c`) through `sm_get_class_with_statistics()`. The optimizer uses:

- `heap_num_objects` — table cardinality for cost estimation
- `heap_num_pages` — for full-scan I/O cost
- `BTREE_STATS.keys` / `pkeys` — for index scan cardinality and selectivity
- `BTREE_STATS.height`, `leafs`, `pages` — for index seek and range scan cost

### 11.6 xserver_interface.h

`xstats_get_statistics_from_server` is declared in `src/base/xserver_interface.h` — the interface header that declares all cross-boundary `x`-prefixed server entry points. This is the interface used by both `network_interface_sr.cpp` (the CS_MODE server dispatcher) and `network_interface_cl.c` (the SA_MODE direct-call path).

## 13. Notable Patterns & Idioms

### 13.1 `free_and_init` vs `db_ws_free`

The file uses two distinct deallocation patterns based on which allocator was used:

- `db_ws_free(ptr)` — for workspace-allocated objects (`CLASS_STATS`, `ATTR_STATS`, `BTREE_STATS`, `pkeys`). These live in the workspace and have workspace lifecycle.
- `free_and_init(ptr)` — for `malloc`-allocated objects (`select_list`, `query_buf`, `attr_ndv` in NDV path). The `free_and_init` macro calls `free()` and then sets the pointer to NULL, preventing use-after-free.

This separation is a strict CUBRID project rule: never call bare `free()`.

### 13.2 Partial-unwind error recovery in unpack

```c
attr_stats_p->bt_stats = db_ws_alloc(...);
if (attr_stats_p->bt_stats == NULL) {
    stats_free_statistics (class_stats_p);
    return NULL;
}
```

Rather than tracking individual allocations, the code relies on `stats_free_statistics` to handle partially-initialized structures. This is possible because all pointer fields are initialized to NULL (via `memset` for the `BTREE_STATS` array, and implicit zero-init for individual fields read from wire in order).

### 13.3 Timestamp-based lazy cache coherency

The client-side statistics cache uses a `time_stamp` field as a lightweight version vector. This avoids sending statistics data on every query plan compilation when statistics have not changed — an important optimization for high-throughput OLTP workloads where the same tables are queried repeatedly.

The protocol is one-sided: the client always informs the server of its current timestamp, and the server decides whether to send new data. This is simpler than a two-phase cache validation protocol.

### 13.4 Defensive clamping of statistics values

After deserialization, `keys` and `pkeys[k]` are capped:

```c
btree_stats_p->keys = MIN (btree_stats_p->keys, class_stats_p->heap_num_objects);
btree_stats_p->pkeys[k] = MIN (btree_stats_p->pkeys[k], btree_stats_p->keys);
```

This prevents the optimizer from computing a selectivity > 1 (or < 0) due to stale/inconsistent statistics. Statistics can become inconsistent when rows are inserted/deleted between statistics updates.

### 13.5 NDV = 0 replaced with NDV = 1

```c
class_attr_ndv->attr_ndv[i].ndv = DB_GET_BIGINT (&value) == 0 ? 1 : DB_GET_BIGINT (&value);
```

A column where every value is NULL would return `COUNT(DISTINCT col) = 0`. The optimizer uses NDV as a denominator for selectivity estimates; a 0 NDV would cause division by zero. Setting it to 1 is the safe minimum.

### 13.6 LOB/JSON/wide-VARCHAR skip in NDV

```c
if (TP_IS_LOB_TYPE (...) || TP_DOMAIN_TYPE (dom) == DB_TYPE_JSON ||
    (TP_IS_CHAR_TYPE (...) && dom->precision > STATS_MAX_PRECISION))
{
    snprintf (column, 23, "cast (-1 as BIGINT), ");
}
```

These types are too large or semantically inappropriate for `COUNT(DISTINCT ...)`. The sentinel value `-1` signals the consumer that NDV is unavailable for this column. The threshold `STATS_MAX_PRECISION = 4000` limits statistics to VARCHAR columns up to 4000 characters; wider strings are skipped.

### 13.7 `goto end` cleanup pattern

`stats_get_ndv_by_query` and `stats_make_select_list_for_ndv` use the `goto end` cleanup idiom pervasive in CUBRID's C code:

```c
int error = NO_ERROR;
// ... allocations ...
if (something_failed) {
    error = ER_FAILED;
    goto end;
}
// ... more work ...
end:
  free_and_init (buf1);
  free_and_init (buf2);
  if (result) db_query_end (result);
  return error;
```

This avoids duplicating cleanup code across multiple error paths while keeping the happy path linear.

### 13.8 SAMPLING_SCAN hint

```c
query = "SELECT /*+ SAMPLING_SCAN */ %s FROM [%s]";
```

The `/*+ SAMPLING_SCAN */` optimizer hint instructs CUBRID's query executor to scan a statistical sample of leaf pages from each index rather than the full heap. The sample size is controlled by `STATS_SAMPLING_LEAFS_MAX` (5000 pages) and `NUMBER_OF_SAMPLING_PAGES` (5000). This allows rapid NDV estimation for large tables without a full sequential scan, at the cost of accuracy.

### 13.9 `dedup_idx` field and its display logic

```c
int pkeys_size = (bt_stats_p->dedup_idx >= 0) ? bt_stats_p->dedup_idx : bt_stats_p->pkeys_size;
for (k = 0; k < pkeys_size; k++) { ... }
```

The `dedup_idx` field supports `SUPPORT_DEDUPLICATE_KEY_MODE` — a mode where the B+tree index appends a deduplication suffix key to distinguish otherwise-identical key tuples. The `dedup_idx` marks the boundary between user-visible key columns and the dedup suffix. When dumping statistics, only columns up to `dedup_idx` (exclusive) represent actual user-visible cardinality. The assertion `assert(bt_stats_p->dedup_idx != 0)` reflects that 0 is not a valid state — `dedup_idx` must be either positive (dedup at that position) or negative (no dedup).
